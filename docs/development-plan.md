## 交付顺序

优先保护构建目录和导出成果，再确认 worker 故障恢复，最后形成可验证的发布候选。依赖审计可并行开展。

| 顺序 | 工作项 | 依赖 | 完成标志 |
| --- | --- | --- | --- |
| 1 | S1 构建输出目录保护 | 无 | 错误路径在任何删除前被拒绝；合法构建成功 |
| 2 | S2 普通导出完整提交 | 无，可与 S1 并行 | 失败或取消不留下可误认为成功的导出目录 |
| 3 | S3 worker 故障恢复验证 | 无，可与 S1 并行 | 超时、取消和异常响应后可继续处理下一任务 |
| 4 | S4 文档资源边界 | S3；先确定限额 | 超限输入可预期失败，资料及主界面可继续使用 |
| 并行 | S5 依赖审计与分发许可 | 可访问依赖源与上游许可 | 审计结论、处置和随包声明齐全 |
| 收口 | S6 发布候选与升级验收 | S1–S5；隔离 Windows 环境 | 回归、打包、升级、备份恢复及产物校验有记录 |

默认按此顺序推进。S4 的具体数值需由正常样本和机器配置测量后确定；如调整发布范围，在对应 Issue 记录原因、影响与剩余工作。

## S1：保护 worker 构建输出目录

**依据。** [build-worker.ps1](../worker/document-worker/build-worker.ps1) 将 `OutputDirectory` 转为绝对路径后，会递归删除已有目录；当前缺少专用输出目录边界检查。

**范围。** 在清理前校验最终解析路径，只允许明确的构建输出位置。保留桌面 publish 使用的 `obj/document-worker` 与独立构建的 `artifacts/document-worker`；若需要其他位置，定义明确的专用目录契约。

**验收。** 用临时测试目录覆盖合法重建、根目录、仓库根、源码目录、祖先目录和目录联接；拒绝路径中的标记文件保持不变。输出路径校验完成后，再进行实际打包验证。

**建议下一步立即领取此项。** 范围小，直接影响下一轮打包安全，能够用临时夹具验证。

## S2：普通导出完整提交

**依据。** [ReimbursementBatchExporter](../src/Eiri.Reimbursement.Infrastructure/Export/ReimbursementBatchExporter.cs) 直接创建最终导出目录；失败时只清理临时渲染目录，可能留下部分 CSV、图片和原件。

**范围。** 在目标父目录下的专用暂存目录生成整个批次，全部成功后再提交为最终目录；维持现有命名、CSV 列和打印材料布局。成功后的里程碑更新沿用现有桌面编排。

**验收。** 渲染失败、复制失败、取消、同名冲突和提交失败均不损坏既有导出或用户文件；失败不更新已导出里程碑。成功仅产生一个完整批次；清理失败有明确提示。文件提交后若数据库保存失败，保留完整文件并提示状态未保存。

**验证入口。** [导出服务测试](../tests/Eiri.Reimbursement.Infrastructure.Tests/ReimbursementBatchExporterTests.cs)与桌面导出调用。审批 PDF 的独立临时文件提交行为保持一致。

## S3：worker 故障恢复验证

**依据。** [进程适配器](../src/Eiri.Reimbursement.Infrastructure/Documents/JsonLinesProcessDocumentProcessor.cs) 已有超时、取消和终止进程树逻辑；[对应集成测试](../tests/Eiri.Reimbursement.Infrastructure.Tests/JsonLinesProcessDocumentProcessorTests.cs)目前只覆盖两种成功路径。

**范围。** 扩展可控假 worker，验证进程和协议失败边界；发现缺陷后按失败用例修复。

**验收。** 覆盖超时、取消、非零退出码、空响应、坏 JSON、协议版本不符及转图越界路径；每条路径返回可理解的错误，进程结束，下一任务成功。已有人工校正、原始文件和业务记录保持完整；异常输出不得成为可用导出结果。

## S4：确定并落实文档资源边界

**依据。** worker 逐页以 300 DPI 渲染。当前实现具备超时，尚未发现文件大小、PDF 页数、总渲染像素和进程内存配额。钉钉媒体上传的 20 MB 限制仅适用于上传图片。

**先做限额决策。** 用正常脱敏材料和合成大文档测量时间与峰值内存，为导入大小、页数、单页及总像素选择限额，明确各操作的适用范围和超限提示。将数值与依据放进实现工单后再开发。

**验收。** 超限检查在昂贵的解码或分配前生效；覆盖恰好达到限额、超过限额、损坏 PDF、加密 PDF 和中途取消。失败后可重试其他材料，原件和人工校正保留。发布记录写明实际覆盖的限制；进程内存隔离策略单独说明。

## S5：依赖审计与分发许可

**依据。** [Build-Msi.ps1](../installer/Build-Msi.ps1) 的构建步骤关闭 `NuGetAudit`；v0.5.0 发布记录明确未完成在线依赖漏洞审计。

**范围。** 盘点 NuGet、Python、打包工具、PDFium、OCR 模型及发布包中的其他组件，使用其官方来源核对漏洞、许可证和分发声明。审批 PDF 使用本机字体，需同时核对字体实际使用与分发边界。

**验收。** 记录组件版本、来源、审计日期、发现项和处置；应随包提供的声明进入 MSI 与 ZIP。无结果、离线或工具失败单独记录，修复后重新验证受影响的识别、转图和审批 PDF。此项的在线审计命令与执行入口见[开发指南](development.md)。

## S6：形成发布候选

**范围。** S1–S5 完成后冻结本次变更，确定新版本号并更新桌面项目；按[开发与交付指南](development.md)打包。

**发布验收：**

- 当前源码的 .NET 与 Python 回归通过；覆盖设置保存、启动重连失败后重试、OCR 回退及人工校正保护。
- 打包 worker 在没有开发虚拟环境的条件下完成文本提取、OCR、转图和审批 PDF。
- 手工检查点击、键盘与拖放导入，默认导出目录和浅色/深色界面；核对失败后重试与状态提示。
- 在未安装本产品的隔离 Windows 环境完成 v0.5.0 → 候选版升级：已有订单、材料、审批记录和连接信息保留，schema 14 可再次打开；默认导出设置按其本地文件存储规则验证。
- 检查旧版备份恢复、恢复后重启、安装目录和资料库目录保留，以及卸载保留/删除测试边界。
- MSI 完整 payload、图标、升级规则及 ZIP 文件清单通过，分别生成 SHA-256；确认分发声明随包提供。
- 新发布记录写入实际命令、环境、结果及剩余限制；将已交付条目从未发布记录移入对应版本。

钉钉真实流程已有历史验收；若本阶段改动请求契约或提审逻辑，针对受影响路径重新验收。

## 稳定版本之后

1. **识别与性能基线。** 建立获准的脱敏样本、标准答案和可重复运行报告，按文本 PDF、扫描件、混合页、红字发票等类型统计字段准确率、人工核对率、冷启动与单文件耗时。早期目标为发票号/金额 99%、商家 98%、明细 95%，达标情况等待测量。
2. **容量验收。** 以 10,000 个订单、50,000 个文件验证列表、查询、备份恢复及导出，记录机器和数据分布后再确定性能门槛。
3. **高对比模式。** 当前主题覆盖部分系统颜色资源；先在 Windows 高对比模式下核实可读性与焦点，再界定适配范围。

XLSX、普通 PDF 合并、自动匹配、云端 OCR、多人协作、移动端、应用内账号与导出历史继续暂缓。后续功能进入开发前，先明确使用场景，再按 ask-matt 的 spec → tickets → implement 流程拆分。
